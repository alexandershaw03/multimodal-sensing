# Synchronisation Architecture

## Overview

The system combines data generated by multiple independent sources:

* EEG acquisition
* experimental cue and event markers
* camera-derived human kinematics
* detected movement events

These streams operate at different sample rates and are generated by different software processes. A central engineering requirement is therefore to preserve sufficient timing information to reconstruct the temporal relationship between them after recording.

The current implementation uses **Lab Streaming Layer (LSL)** as the software data transport and timing layer, with **XDF** used as the multimodal recording format.

The objective is not simply to store several sensor streams in the same file, but to make events in one modality comparable against events in another.

---

## Data Flow

```text
 EEG acquisition
       │
       ▼
  EEG LSL stream
       │
       │
       ├─────────────────────┐
       │                     │
       │                     ▼
       │              LabRecorder
       │                     │
       │                     ▼
       │                 XDF file
       │                     ▲
       │                     │
       ├─────────────────────┤
       │                     │
Experiment markers      Vision / motion
       │                     │
       ▼                     ▼
 Marker LSL stream      Motion data stream
```

Each modality retains its own sequence of samples and timestamps while being recorded into the same multimodal XDF session.

---

## Why Synchronisation Matters

For a motor-response experiment, several different events can describe what appears superficially to be one action:

```text
cue displayed
      │
      ▼
neural activity
      │
      ▼
movement initiated
      │
      ▼
visible physical motion
```

These events are not interchangeable.

For example, aligning EEG to the experimental cue answers a different question from aligning EEG to the independently observed onset of physical movement.

The current pipeline therefore preserves both timing references.

---

## EEG Stream

The EEG acquisition process publishes live EEG samples through an LSL outlet.

The current headset provides five EEG channels:

```text
AF3
T7
Pz
T8
AF4
```

Samples are transmitted as a continuous stream and recorded alongside the other active LSL streams.

The EEG stream is subsequently extracted from XDF and converted into an MNE-compatible representation for analysis.

---

## Experimental Marker Stream

Experimental events are transmitted separately from the EEG samples.

Representative markers include events such as:

```text
LEFT
RIGHT
movement start
movement stop
blink
rest
```

Separating markers from the continuous EEG stream has several advantages:

* event timing is explicitly represented
* experiment logic remains independent of EEG acquisition
* additional event types can be introduced without modifying the EEG sample format
* events can be aligned against any other recorded modality

The marker stream therefore acts as the experimental timeline.

---

## Vision-Derived Motion

Camera-based pose estimation provides an independent physical measurement of subject behaviour.

Derived quantities currently include measurements such as:

* wrist position
* relative wrist displacement
* wrist speed
* elbow angle
* movement onset

The important distinction is that the vision system does not simply reproduce the commanded experiment label.

It provides an independent observation of what physically happened.

This allows the system to distinguish:

```text
commanded action
       ≠
observed action
```

and enables invalid or incorrectly performed trials to be rejected before EEG analysis.

---

## Behavioural Validation

For each commanded motor trial, the validation stage compares:

```text
experimental cue
       │
       ▼
expected movement
       │
       ▼
vision-derived movement
       │
       ▼
validated / rejected
```

Only behaviourally valid trials are passed into the current event-aligned EEG analysis.

For valid trials, reaction time is calculated as:

```text
reaction time =
detected movement-onset time
-
cue time
```

This also produces two independent event references for EEG epoch generation:

```text
cue-aligned EEG
```

and:

```text
movement-onset-aligned EEG
```

This distinction is central to the current analysis architecture.

---

## XDF as the Recording Layer

The complete multimodal session is recorded into an XDF file.

Conceptually, the recording contains:

```text
XDF session
│
├── EEG samples + timestamps
│
├── experimental markers + timestamps
│
└── motion-derived measurements + timestamps
```

The analysis software can therefore reconstruct the relative timing of events without requiring each stream to have the same sample rate.

This is particularly useful for heterogeneous sensing systems where one modality may produce continuous high-rate samples while another produces sparse asynchronous events.

---

## Offline Alignment

During analysis, timestamps from each stream are converted into a common relative experiment timeline.

A simplified representation is:

```text
absolute stream timestamps
          │
          ▼
 choose recording reference
          │
          ▼
relative experiment time
          │
     ┌────┴─────┐
     ▼          ▼
EEG samples   events / motion
     │          │
     └────┬─────┘
          ▼
   temporal alignment
```

This allows visualisation and analysis of heterogeneous signals on the same horizontal time axis.

The resulting multimodal timeline can therefore show EEG, physical motion and experimental events together.

---

## Event-Aligned Analysis

Once valid event times have been identified, continuous EEG can be segmented into epochs around specific events.

### Cue alignment

```text
           cue
            │
            ▼
────────────┼────────────
     pre    0     post
```

This measures EEG relative to the experimentally commanded event.

### Movement alignment

```text
       movement onset
            │
            ▼
────────────┼────────────
     pre    0     post
```

This measures EEG relative to the independently detected physical response.

Maintaining both references prevents the behavioural reaction-time delay from being silently incorporated into all neural analyses.

---

## Current Synchronisation Limitations

The current architecture provides useful software-level temporal alignment, but it is not a hardware-synchronised measurement system.

Important limitations include:

### No shared hardware trigger

The EEG system, computer vision system and experimental software do not currently receive a common electrical timing pulse.

Synchronization therefore depends on software timestamps rather than a directly observed shared hardware event.

### Sensor acquisition latency is not fully characterised

A timestamp recorded by software does not necessarily represent the exact physical instant at which a sensor measurement occurred.

Potential delays include:

```text
physical event
    ↓
sensor exposure / sampling
    ↓
device processing
    ↓
communications
    ↓
software processing
    ↓
timestamp / stream publication
```

These delays have not yet been independently measured for every modality.

### Camera processing adds uncertainty

Vision-derived movement timing depends on:

* camera frame rate
* image exposure timing
* frame transfer
* pose-estimation processing
* movement-onset detection logic

The detected movement timestamp should therefore be treated as an estimate of physical movement onset rather than a laboratory-grade ground-truth timestamp.

### Software scheduling introduces jitter

The current implementation runs on general-purpose operating systems rather than a deterministic real-time platform.

Process scheduling, buffering and communications can therefore introduce timing jitter.

### Residual alignment error has not yet been quantified

The current system demonstrates multimodal alignment functionally, but a formal measurement of absolute synchronisation error has not yet been completed.

This is an important target for future validation.

---

## Planned Timing Validation

A useful next validation stage would introduce an event that can be independently observed by multiple modalities.

For example:

```text
                 ┌── electrical / software marker
hardware trigger ┤
                 └── LED visible to camera
```

The known trigger time could then be compared against:

* marker-stream timestamp
* camera-detected LED transition
* recorded sensor event
* processed event time

This would allow direct measurement of:

```text
offset
jitter
latency
drift
```

rather than assuming that stream alignment is exact.

---

## Future Architecture

A more rigorous distributed sensing system could extend the current architecture with:

* source-side timestamps
* receive-side timestamps
* monotonic clocks
* packet sequence numbers
* explicit latency measurements
* clock-offset monitoring
* hardware triggers
* hardware timestamping
* deterministic acquisition processes
* shared clock distribution or precision time synchronisation where appropriate

A future stream packet could therefore preserve both measurement time and transport behaviour:

```text
sample
│
├── sensor timestamp
├── host receive timestamp
├── sequence number
├── sensor ID
└── payload
```

This would allow sensor latency, packet loss and clock behaviour to be analysed independently rather than being hidden inside the measurement stream.

---

## Engineering Principle

The current system treats synchronisation as part of the sensing architecture rather than as a plotting convenience.

The aim is to preserve enough timing information that statements such as:

```text
"this neural event preceded this physical movement"
```

or:

```text
"this movement occurred 700 ms after this cue"
```

can be traced back to explicit recorded timestamps and independently generated events.

The current implementation is therefore best described as a **software-synchronised multimodal prototype**, with hardware-level timing validation identified as a clear next engineering step.
